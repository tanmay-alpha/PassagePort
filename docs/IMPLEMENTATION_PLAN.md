# Implementation plan

Priorities follow the audit in [BASELINE_AUDIT.md](BASELINE_AUDIT.md). Each item lists the acceptance
check used to call it done.

## P0 — correctness, security, persistence

| # | Work | Acceptance |
| --- | --- | --- |
| 1 | Remove server-path ingestion (`/encode_doc`, `/encode_batch`) and URL ingestion (`/ingest_llms_txt`); uploads only | No endpoint accepts a filesystem path or URL; traversal tests pass |
| 2 | Document model: collections → documents → pages → chunks in one SQL store, original files kept | Documents can be listed, renamed, deleted, re-indexed; delete leaves no chunks/blobs (tests) |
| 3 | Upload validation: size cap, extension + content sniffing, zip-bomb guard, sha256 dedup | Adversarial upload tests pass |
| 4 | Parsing in a killable subprocess with limits; PDF/TXT/MD/DOCX | Malformed, encrypted and oversized inputs fail with a clear message, server keeps serving |
| 5 | Indexing as a leased background job with crash recovery | Expired-lease job is retried; data survives restart (test + E2E) |
| 6 | Auth boundary: `local` mode loopback-only; `accounts` mode with real sessions and per-user isolation | Cross-user access returns 404 on every endpoint (tests) |
| 7 | Page-accurate citations with stable chunk IDs | `page.text[start:end] == chunk.text` property test; E2E opens the cited page |

## P3 — deliberately out of scope

OCR for scanned PDFs, ANN indexes for very large collections, streaming LLM responses, shared
collections between accounts, multilingual default model. Each is noted where relevant in the docs.
